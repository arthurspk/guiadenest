## :dart: O guia para alavancar a sua carreira

> NestJS é o framework Node.js mais usado para construir back-ends de nível empresarial: arquitetura modular inspirada no Angular, TypeScript de primeira classe, injeção de dependência, suporte nativo a REST, GraphQL, microsserviços e WebSockets, e um ecossistema de módulos oficiais (`@nestjs/typeorm`, `@nestjs/swagger`, `@nestjs/cqrs`, `@nestjs/schedule`) que resolve praticamente qualquer necessidade de uma API real. É a escolha padrão de times que já sabem JavaScript/TypeScript e querem organização e escalabilidade sem abrir mão da produtividade do Node. Este guia reúne roadmap, documentação oficial, cursos gratuitos e pagos, canais, ferramentas do ecossistema e um capítulo sobre usar IA na prática com NestJS — tudo verificado, com prioridade para conteúdo gratuito e em português.

## 🗺️ Roadmap
- [NestJS 12 is Now Available (blog oficial da Trilon)](https://trilon.io/blog/nestjs-12-is-now-available) — Anúncio oficial da versão mais recente do framework (2026): pacotes ESM-first, Vitest e oxlint como padrão, Rspack, validação com Standard Schema e observabilidade nativa.
- [Announcing NestJS 11: What's New (blog oficial da Trilon)](https://trilon.io/blog/announcing-nestjs-11-whats-new) — Anúncio oficial da versão 11 (2025), com as mudanças que antecederam a 12.
- [nestjs/nest — Releases](https://github.com/nestjs/nest/releases) — Histórico completo de versões do framework, direto do repositório oficial.
- [roadmap.sh — Backend Roadmap](https://roadmap.sh/backend) — Roteiro da comunidade sobre o caminho até back-end profissional; útil para situar onde o Node.js e frameworks como o Nest entram na jornada.

**Trilha resumida** (siga na ordem; cada etapa tem recursos nas seções abaixo):

1. **Fundamentos de JavaScript/TypeScript** — variáveis, funções, classes, tipos, decorators. O Nest pressupõe TypeScript intermediário.
2. **Fundamentos de Node.js** — event loop, módulos, npm, requisições HTTP.
3. **Primeiro projeto Nest** — instalação via Nest CLI, estrutura de módulos, controllers e providers.
4. **Injeção de dependência e módulos** — o coração da arquitetura do framework, inspirada no Angular.
5. **Persistência de dados** — TypeORM, Prisma ou Mongoose, DTOs e validação com `class-validator`.
6. **Autenticação e autorização** — Passport, JWT, Guards e Interceptors.
7. **Testes** — Jest para testes unitários e e2e, um dos pontos fortes do framework.
8. **APIs além do REST** — GraphQL, WebSockets e microsserviços (Redis, RabbitMQ, Kafka, gRPC).
9. **Produção** — Docker, variáveis de ambiente, logging, observabilidade (Terminus, OpenTelemetry).
10. **Especialização** — CQRS, arquitetura hexagonal/DDD, monorepos com Nest Devtools.

## 🚀 Por onde começar
1. **Instale o Node.js e o Nest CLI**, depois crie seu primeiro projeto com `npm i -g @nestjs/cli && nest new meu-projeto` — veja o guia oficial de [Primeiros passos](https://docs.nestjs.com/first-steps).
2. **Leia a introdução da documentação oficial** — [First Steps](https://docs.nestjs.com/first-steps), [Controllers](https://docs.nestjs.com/controllers) e [Providers](https://docs.nestjs.com/providers) — para entender a estrutura inicial de um projeto.
3. **Entenda o sistema de módulos** — [Modules](https://docs.nestjs.com/modules) — como o Nest organiza a aplicação em blocos independentes e reutilizáveis.
4. **Assista a um curso em vídeo em português** em paralelo à leitura da documentação — veja a seção [🔤 Sites e cursos](#-sites-e-cursos-para-aprender-nestjs) abaixo.
5. **Explore o starter oficial em TypeScript** — [nestjs/typescript-starter](https://github.com/nestjs/typescript-starter) — o esqueleto que o próprio `nest new` usa por baixo dos panos.
6. **Aprenda a gerar código com o CLI** — [CLI Overview](https://docs.nestjs.com/cli/overview) e o [gerador de CRUD](https://docs.nestjs.com/recipes/crud-generator) — para criar módulos, controllers e services em segundos.
7. **Conecte um banco de dados** — [Database](https://docs.nestjs.com/techniques/database) — TypeORM, Prisma ou Mongoose, conforme o projeto.
8. **Publique um projeto** — planos gratuitos como Railway, Render ou Fly.io funcionam bem para começar (veja [🛠️ Ferramentas](#️-ferramentas)).

Seu primeiro projeto em poucos comandos:

```bash
npm i -g @nestjs/cli
nest new meu-projeto
cd meu-projeto
npm run start:dev
```

## 🛠️ Ferramentas
### Bancos de dados e ORMs
- [TypeORM](https://typeorm.io/) — O ORM mais usado com Nest, com suporte oficial via `@nestjs/typeorm`.
- [Prisma para NestJS](https://www.prisma.io/nestjs) — Guia e integração oficial do Prisma ORM com aplicações Nest.
- [Mongoose](https://mongoosejs.com/) — ODM para MongoDB, com suporte oficial via `@nestjs/mongoose`.

### Validação e serialização
- [class-validator](https://github.com/typestack/class-validator) — Biblioteca de decorators para validar DTOs, usada oficialmente pelos Pipes do Nest.
- [class-transformer](https://github.com/typestack/class-transformer) — Biblioteca para transformar objetos simples em instâncias de classes e vice-versa, usada junto com o class-validator.
- [Zod](https://zod.dev/) — Biblioteca de validação de esquemas com inferência de tipos, alternativa moderna ao class-validator em projetos Nest.

### Autenticação e filas
- [Passport.js](https://www.passportjs.org/) — Middleware de autenticação usado pelo módulo oficial `@nestjs/passport`.
- [BullMQ (documentação)](https://docs.bullmq.io/) — Biblioteca de filas baseada em Redis, com integração oficial via `@nestjs/bullmq`.

### DevOps, deploy e observabilidade
- [Docker](https://www.docker.com/) — Containerização de aplicações Nest para desenvolvimento e produção.
- [Railway](https://railway.com/) — Plataforma de deploy com camada gratuita, popular para publicar APIs Nest rapidamente.
- [Render](https://render.com/) — Plataforma de hospedagem com camada gratuita, alternativa ao Railway para APIs Node.js.
- [Fly.io](https://fly.io/) — Plataforma para rodar aplicações (incluindo Docker) perto dos usuários, com camada gratuita para projetos pequenos.
- [PM2](https://pm2.keymetrics.io/) — Gerenciador de processos para manter aplicações Node.js/Nest rodando em produção.
- [Mau (deploy oficial do NestJS)](https://mau.nestjs.com/) — Ferramenta oficial da equipe do Nest para deploy simplificado na AWS.
- [Nest Devtools](https://devtools.nestjs.com/) — Ferramenta oficial para visualizar o grafo de módulos e dependências de uma aplicação Nest em tempo real.
- [Nest Observe](https://observe.nestjs.com/) — Ferramenta oficial de observabilidade da equipe do Nest, com métricas e tracing nativos.

### Qualidade e testes
- [Jest](https://jestjs.io/) — Framework de testes padrão do Nest, já configurado em todo projeto criado pelo CLI.
- [Supertest](https://github.com/forwardemail/supertest) — Biblioteca para testar endpoints HTTP, usada nos testes e2e oficiais do Nest.
- [ESLint](https://eslint.org/) — Linter padrão configurado nos projetos gerados pelo Nest CLI.
- [Prettier](https://prettier.io/) — Formatador de código, também configurado por padrão nos projetos Nest.
- [Compodoc](https://compodoc.app/) — Gerador de documentação estática a partir do código-fonte, compatível com projetos Nest (por compartilhar a mesma estrutura de decorators do Angular).

### Testando a API
- [Postman](https://www.postman.com/) — Cliente REST/GraphQL para testar endpoints durante o desenvolvimento.
- [Insomnia](https://insomnia.rest/) — Alternativa ao Postman, cliente REST/GraphQL open source.

## 🤖 IA na prática
O NestJS é extremamente bem documentado e segue convenções fortes (decorators, módulos, injeção de dependência), o que faz com que assistentes de código sejam muito bons para gerar boilerplate (controllers, services, DTOs, testes). Por outro lado, a IA erra com frequência em detalhes de injeção de dependência entre módulos e em misturar convenções de versões diferentes do framework.

**Para aprender**
- Peça para a IA explicar um erro de injeção de dependência (`Nest can't resolve dependencies`) e sugerir como corrigir sem quebrar a arquitetura modular.
- Peça exercícios com testes usando Jest sobre o tópico que está estudando: você escreve a solução, o teste diz se passou.
- Peça para transformar um controller com lógica de negócio direta em um design com Service + Repository, e explicar o porquê da separação.
- Use a IA para revisar a estrutura de um novo módulo (imports, providers, exports) antes de rodar a aplicação.

**Para trabalhar**
- Use GitHub Copilot, Cursor ou Claude Code para gerar DTOs, Pipes de validação e testes Jest a partir das entidades do banco, e explicar queries TypeORM/Prisma complexas.
- Peça para a IA gerar a documentação Swagger (`@ApiProperty`, `@ApiOperation`) de um endpoint já existente — é um dos usos mais produtivos e de menor risco.
- [Inside an AI Voice Agent Backend: A NestJS + Drizzle Architecture Walkthrough (Ganesh Bora)](https://dev.to/ganesh_bora_12e6afdf2c7f0/inside-an-ai-voice-agent-backend-a-nestjs-drizzle-architecture-walkthrough-1o0d) — Estudo de caso gratuito sobre construir um back-end de agente de voz com IA usando NestJS.
- [GitHub Copilot](https://github.com/features/copilot) — Autocomplete e chat com IA no editor; gratuito para estudantes e com plano free.
- [Cursor](https://cursor.com/) — Editor baseado no VS Code com IA integrada ao fluxo de trabalho.
- [Claude Code](https://code.claude.com/docs/en/overview) — Agente de código no terminal: escreve testes Jest, gera módulos e explica erros de injeção de dependência.

**Limites e boas práticas**
- IA **inventa métodos e decorators** que não existem na versão instalada do Nest — confira sempre a versão real do projeto (`package.json`) contra a documentação oficial.
- Desconfie de sugestões que injetam repositórios ou serviços sem passar pelo sistema de módulos do Nest — quebra o padrão de injeção de dependência e cria acoplamento escondido.
- Nunca aceite sugestões que exponham segredos (`JWT_SECRET`, credenciais de banco) direto no código ou desativem `ValidationPipe`/CORS sem necessidade real.
- Migrations de TypeORM/Prisma geradas por IA precisam ser lidas por um humano antes de rodar em produção — reverter uma migration aplicada num banco com dados reais pode ser destrutivo.
